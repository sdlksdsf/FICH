18 checks. Read it once, fix what you fail.

🛡️ ShipCheck

Ship-Ready

The 18 checks that separate a demo from an app that can take money. Written for anything built with Lovable, Bolt, Cursor, Replit, v0 or an AI agent that wrote most of the code before you read it.

Why these 18

Every item here is a failure that does not appear in testing, because testing does not involve a real card, a hard refresh, a second user, or a stranger reading your JavaScript. They show up in week one of real traffic, when they are expensive.

01–04 The blockers

Each of these loses you money or data. Fix these before you take a single payment.

Blocker

Payment confirms nothing

01

The checkout completes and the card is charged, but no entitlement is written. The customer pays and gets nothing, and you find out from a support email.

How to check

Look at your webhook handler. Does it verify the signature, then write a row, then return 200 — in that order? If fulfilment happens in the browser on a "success" redirect, you have this bug.

Fix
Fulfil on the webhook, never on the redirect. Verify the signature, make the write idempotent with the event ID as a unique key, and return 200 even if the row already exists.
~60 min
Blocker

Page 404s on hard refresh

02

Client-side routing works while you click around. Paste the same URL into a new tab and it breaks, so every link you share with a customer is a dead end.

How to check

Open a deep route in a fresh incognito tab. Then send it to yourself. If it only works after navigating from the homepage, it fails.

Fix
Add a catch-all rewrite to index.html on your host, and make sure your API and asset paths are excluded so they are not swallowed.
10 min
Blocker

A secret is in the browser bundle

03

A service-role key, a Stripe secret, or an admin token got imported somewhere reachable by the client. Anyone can read it and act as you.

How to check

Build for production, open the output JS, and search for service_role, sk_, secret. Anything that turns up is public.

Fix
Rotate the key first — assume it is compromised. Move the call to a server function. Keep only the publishable key in the client.
45 min
Blocker

Protected pages render before auth resolves

04

The dashboard paints for a moment before the session check completes. On a slow connection that moment is long enough to read, screenshot, or interact with.

How to check

Throttle the network to slow 3G, sign out, and load a protected route directly. Watch whether any real content appears.

Fix
Gate on an explicit loading state that renders null. Redirect only after the auth state is known, not while it is still resolving.
30 min

05–12 The silent failures

Nothing crashes. Things just quietly do not work, which is worse.

High

Row-level security is off

05

Every table readable by any authenticated user. One signup and someone can read your whole customer base.

How to check

Query a table with an anonymous key. If you get rows back, RLS is off or the policy is true.

Fix
Enable RLS on every table, then add per-user policies. Default deny, then open exactly what each role needs.
2–4 hrs
High

Env vars missing in production

06

Works locally because your .env has it. Deployed, it is undefined, and the feature fails silently.

How to check

List every environment variable the code reads. Compare against what the host actually has set.

Fix
Fail loudly at boot if a required variable is absent. A crash on deploy beats a feature that half-works.
30 min
High

localhost is still in the shipped code

07

An API base URL or a redirect still points at your machine. It works for you and for nobody else.

How to check

Search the source for localhost and 127.0.0.1.

Fix
Move it to an env var with the production value as the default, and delete the fallback.
15 min
High

Failed writes look like success

08

The insert throws, nothing catches it, and the UI says "Saved". Data disappears and the user trusts it.

How to check

Find every write. Is the error handled, and does the UI change only after it resolves?

Fix
Check the error on every mutation before showing success. Roll back optimistic UI on failure.
1–2 hrs
High

No rate limit on anything that costs money

09

An AI endpoint, a signup, or an email sender with no cap. One script drains your credits overnight.

How to check

Find every route that calls a paid API or sends mail. Does it have a per-user or per-IP limit?

Fix
Add a counter keyed by user ID with a short window, and a hard monthly ceiling per account.
1 hr
High

Nobody can recover a password

10

The reset flow was never wired to a real mail provider, so it silently does nothing. You lose the customer permanently.

How to check

Run a reset for a real address you control. Did the mail actually arrive?

Fix
Send through a transactional provider with a verified domain. Test the full loop, including the link.
1 hr
High

No error boundary

11

One malformed API response and the whole app goes white. The user has no idea whether they were charged.

How to check

Throw deliberately inside a component in staging.

Fix
Wrap the tree in an error boundary that renders a real page with a way back.
30 min
High

Schema only exists in someone's dashboard

12

Tables were created by clicking. There are no migrations, so a restore loses structure and nobody can state the real schema.

How to check

Is there a migrations folder that matches production?

Fix
Dump the schema, commit it, apply through CI from now on.
30 min

13–18 The ones that cost you trust

Not fatal, but they are why someone decides not to come back.

Medium

Session token in localStorage

13

Any injected script reads it and takes the account. Move it to an httpOnly cookie.

40 min
Medium

Secrets printed to logs

14

A console log dumps an env value into a third-party logging service. Log a redacted shape instead.

15 min
Medium

No loading or empty states

15

Blank screens read as broken. A skeleton and a real empty state cost an hour and change the first impression entirely.

1 hr
Medium

Broken links and dead buttons

16

Every CTA that 404s is a customer who was ready to give you money and could not. Click all of them, signed in and signed out.

20 min
Medium

No page titles or meta

17

Every shared link renders as an untitled grey box. Fix the title and OG tags; it is the cheapest credibility you can buy.

20 min
Medium

Nobody tested it on a phone

18

Most of your traffic will be mobile. Check the flow at 375px wide, starting from a cold load.

30 min

The order that matters

If you fix nothing else, fix 01 to 04. Those four are the difference between an app that can hold a customer's money and one that cannot.

  • 01 before you take a single payment
  • 03 before the key has been public for an hour longer than it already has
  • 02 before you share one more link
  • 05 before your second user signs up
